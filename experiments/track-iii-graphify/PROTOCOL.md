# III.G predeclared structural utility protocol

This complementary carveout does not renumber III.10 or authorize integration.
III.8 FAIL and III.8R PASS remain unchanged. Graphify was not incrementally useful
on their structural corpus because lexical discovery already covered all eight targets.

## Frozen corpus and authority

Two public repositories, ten questions each; five each DIRECT, MULTI_HOP, IMPACT,
TRAP. Primary evaluation uses pinned B. Pinned A supplies a genuine checkout-to-B
freshness transition. Only production main Java is indexed: spring-kafka/src/main/java
and Jackson src/main/java. Tests, build execution and downloaded dependencies are out
of scope. repositories.json pins commits and all tracked checkout bytes before queries.
Queries and source-derived oracles are immutable after registration.

No Graphify result supplies oracle truth. Independently inspect Java source declarations,
explicit imports and calls whose local/declared receiver can be resolved. Heritage is
typed: implements differs from inherits. Calls are statically declared connectivity,
not proof of virtual dispatch or runtime impact. Ambiguous overloads, reflection,
external symbols and unresolvable receivers cannot count as supported relations.
The limited source fact extractor supplies revalidation/oracle witnesses, not a new
Graphify implementation. Negative answers mean no supported relation of the specified
type in this scope, not a universal runtime impossibility claim.

## Conditions and equal boundaries

A: three source exploration operations maximum:
1. Repository-wide exact-token rg search, batching both named endpoints for paths,
   with four source context lines on either side. All permitted matches are eligible.
2. Open the start symbol's authoritative source file. This exposes its full source
   facts, including other methods/types in that file; do not hide useful local edges.
3. One repository-wide batched rg search for discovered frontier symbols (both ends),
   again with four context lines. No oracle names are added to this frontier.
Facts admitted from grep require their source statement line in an actual matched
window. Full-file facts are eligible after the file-open operation. Log every search,
file examined, byte count and time. This is a strong deterministic fixed exploration
policy, not a claim of optimal human planning. No unbounded source graph is handed to A.

B: one structural capability request using real pinned Graphify extraction and native
bounded BFS/path machinery; traversal depth is query-specified, at most eight. Cap
native traversal at 2500 nodes / 10000 edges before packet construction; exceeding
limits returns partial/unavailable, not an unbounded substitute. Record native calls
separately from capability round trips. EXTRACTED and INFERRED are kept distinct;
both need source validation. No LLM or semantic extractor runs.

C: the same A exploration plus B, without extra operations. Fuse validated target/edge
identities and preserve discovery provenance. Combined exploration cost includes both
components, rather than pretending combination is cheaper than A.

All conditions use the same authoritative revision, security overlay, source validation
and final selector. Results are typed paths or direct relations, not free-form prose.
All selected edge assertions must be supported by current source facts. A supported
alternative path to the same required endpoint is acceptable. Impact paths identify
structural candidates only. Invalid/stale/forbidden contributions are removed BEFORE
traversal/competition. No externally visible filtered-count diagnostic is emitted.

Order answers by shortest hop count then canonical target identity. Deduplicate node
references in one shared table, preserve edge provenance, and add whole answers while
the complete compact UTF-8 JSON packet (including revision, diagnostics and partial
marker) remains <=2048 bytes. Reserve the longer JSON false marker. No query-specific
weights or oracle-specific exceptions. Selected final packets determine scores.

## Gates fixed before comparative execution

- At least THREE additional unique required targets (repository + canonical target)
  with B or C over A; also report query/answer-pair gains without double-counting them
  as new targets. No mandatory direct target found by A may be lost by C.
- Zero stale or forbidden references in normal packets; all packets <=2048 bytes.
- Trap invalid conclusions with B/C must not exceed A.
- On at least THREE MULTI_HOP/IMPACT queries, B reaches the same or better required
  oracle coverage than A with fewer exploration requests. Report source-revalidation
  files/latency too: validating graph answers is not free. C's total cost is separate.
- Report both repositories and all four categories separately; no opaque average score.
- Stale A-as-B mutation must emit an actual stale reference and fail independent checks.
- Inferred-as-authority mutation admits actual INFERRED edges without type/source
  validation; an unsupported trap conclusion must be caught. If no usable inferred
  edge exists, retain that observation and use a documented genuine structural-trust
  mutation, without changing primary fixtures or gates.

## Freshness, security and operational accounting

Use upstream extract() + directed build_from_json(), with parallel=False, no clustering,
no MCP server and the existing socket-denial guard. Rebuild B with the same parse cache
following A; this is a FULL graph rebuild with a content cache, not an incremental graph
update claim. Retain exact commands, elapsed wall time, peak RSS, graph/cache bytes,
failures/warnings, EXTRACTED/INFERRED counts and A/B edge deltas. Source manifests and
explicit revision identity are checked before any derived result is consumed.

A neutral policy overlay marks selected public source paths synthetic-restricted.
Normal personal bindings exclude their nodes, paths, edges and metadata. This changes
permissions only, never upstream source semantics. Raw administrative indexes may
contain those public fixtures; caller packets and diagnostics must not disclose them.
An isolation fault control may supplement the mandatory two mutations.

Record extraction cost separately from amortized queries. No arbitrary performance
pass threshold. No services, cloud/local cognition, embeddings, production persistence
or unrestricted Graphify MCP adoption. Accept PASS/FAIL/BLOCKED without post-outcome
query, oracle, budget or selector tuning. Classification follows measured utility and
cost, not the presence of a working extractor.
