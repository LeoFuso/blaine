# Context sharding and artifacts

When required context exceeds one worker's useful window, propose coherent research
units within the durable Task. Keep coupled evidence together and follow
[decomposition guidance](orchestration.md). Sharding is not permission for cloud
spend or parallel dispatch; runtime manages execution.

Workers retain compact artifacts in Task-associated storage, rather than returning
full transcripts. An artifact includes only relevant findings, source references
and versions/timestamps, observed facts versus inference, and unresolved questions.
For code analysis, API boundaries, dependencies, mutations, or failure paths may
matter; do not require an exhaustive section template for every workload.

Handoffs contain artifact location, concise findings, material uncertainties, and
critical evidence needing attention. Retrieve sections just in time. Recheck original
evidence when a material decision depends on a compressed finding; resolve conflicts
rather than silently choosing a summary.

Artifacts are evidence and reusable knowledge, not execution state. Restate retains
Task lifecycle; files and conversation summaries must not become a shadow ledger.
Remote workers follow the same provenance and
[sharing restrictions](local-first-and-context.md) as local workers.
