- [P1] Restore the Git authorization and existing-work safeguards — BLAINE.md:90-97

  A cross-service change or new feature is classified as large even when its implementation is tightly coupled and best handled serially, but this execution rule mandates parallel builders. That conflicts with the kernel's requirement that fan-out need independent units that one agent cannot reason about jointly ([BLAINE.md:33–35](../BLAINE.md#L33-L35)); orchestration.md:22 repeats the unconditional large-task mapping. Make parallel execution conditional on the fan-out criteria while retaining risk-appropriate verification, so task size alone neither forces unnecessary workers nor creates an impossible execution contract.

  For a safe local batch operation or development backfill, this sentence now requires explicit approval merely because the work is consequential and long-running. Align the kernel with those gates: retain observability and appropriate recovery planning, but do not make job duration/category alone require a human interruption.
